# Phase A · 实施计划

在同一个 FastAPI 应用和 Jinja 工作台新增本地资产入口，沿用 Python 和 SQLite。新增 Three.js 查看器，以 TypeScript 构建后随 Python 应用提供静态资源。历史 0 A.D. 工作流继续沿用原数据库，本地上传与处理使用独立存储及 SQLite 表。

| 阶段 | 提交门槛 |
| --- | --- |
| B 上传和版本 | 校验文件、ZIP 成员与引用，保存原始文件与 SHA256；验证重复提交、路径与事务 |
| C Blender | 独立输入输出及后台子进程，核实操作符、取消、超时和日志 |
| D QA | 配置化规则、真实 Blender 指标、文件失败报告、未检查状态 |
| E 处理与导出 | 持久任务恢复、用户选择的节点、再导入复检、版本与审核事务、ZIP |
| F 工作台 | 同站导航和本地 Three.js 预览，测试 QA 对照、处理历史和导出 |
| G 验收 | 程序化样本、真实 Blender 与 Mock 分开运行、浏览器和交付文档 |
