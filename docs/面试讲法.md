# ArtPipe 面试讲法

## 三十秒

给游戏项目交一批美术前，审核者需要发现哪些文件会影响导入或玩法，制作人需要知道版本必做任务现在卡在哪里。我把两个老原型接到 0 A.D. 的真实资产和提交历史，做成入库预检、历史回放和评论证据工作台。预检能复现过去已修复的贴图和部件问题。风险卡把动画依赖、返工和授权标到原评论，美术也能在开工前搜已有模型参考。

## 追问

**确定性规则和 LLM 各自解决什么？** 引用目标、重名格式和级别映射可从文件与上下文直接判定。LLM 用于理解评论里的依赖和工作分歧，必须返回原评论 ID 和可以逐字匹配的证据，供制作人核对。

**能证明拦截减少多少延期吗？** 回放验证哪些问题在过去的提交中已经能被规则捕获。里程碑关闭日期与最终计划日期展示历史结果。要估算项目延期因果效果，需要更完整的计划快照、工时和对照实验。

**攻城锤案例是否仍卡在动画？** 评论先出现了动画问题，后续有人承担，风险卡保留这次解除。制作会需要继续核对后来的返工、授权和整体状态。

**中文检索的收益怎么评？** 对照原始文件名、中文词法和词法与图像融合。查询和相关资产先做可复现的候选标注，再由人工复核。哪些问题效果差写在评测里，类别筛选、预览和面数能帮助用户自行判断可复用性。

**与 IEG 怎么对应？** 将开源贡献合并映射到外包交付验收，将 Release 准备映射到版本排期会。当前数据与许可均对应 0 A.D.，迁移时需要团队自己的资产标准和工作权限。
